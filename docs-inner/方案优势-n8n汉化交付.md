# n8n 汉化交付方案优势（存档）

> 存档日期：2026-09-19 ｜ 对应版本：n8n-editor-ui@2.39.8 ｜ 证据指针：README 兼容矩阵、各 Release 说明、CHANGELOG、docs-inner 工作流介绍
> 用途：售前/客户沟通的价值陈述底稿；数字与实证随版本更新，更新时同步改「对应版本」行。

## 一句话

**n8n 每次升级，界面全中文、境内秒拉、一键升降级、不用等人工。**

## 客户价值

### 1. 全量专业汉化（开箱体验）

- **9522 键全量覆盖**：不止界面菜单——节点面板第二层 568 个节点描述、第三层 582 个操作标题全中文，业务人员逐个浏览「这个节点是干嘛的」全程无英文
- **术语体系统一**（727 处大修）：智能体 / 凭据 / 工作流 / 脱敏 / 尊称「您」——同一概念不再多种译法混用，培训成本与沟通歧义直接下降
- **错译清零**：语义级修正（「返回人工客服→返回智能体」「跑步→运行中」「总病例数→用例总数」），避免业务误读
- **弹窗硬编码清零**：「Data Tables」等关键按钮不再中英夹杂

### 2. 升级零负担（运维体验）

- **境内直拉稳定**：华为云 SWR（`swr.cn-north-4.myhuaweicloud.com/bcphub/n8n-chinese`），实测 11 秒级拉取——告别 GitHub Releases 超时 / DockerHub 限流 reset
- **升级 = 改一个版本号**：镜像整体交付免挂载、免下载、免替换（`docker compose pull && up -d`）；回滚 = 改回旧 tag，数据卷零动
- **版本不会选错**：兼容矩阵精确到版本区间，每版 Release 说明写明兼容边界与就近规则
- **Queue Mode 齐套**：`n8n-runners:<ver>` 与主镜像同渠道同版本，worker 集群境内拉取不断供

### 3. 升中文版 = 同时拿到官方修复

- 汉化只替换前端静态文件，**不碰后端 / 数据库 / 配置**——升中文不牺牲官方稳定性，替换与回滚零风险
- 实例：2.39.8 随版带入上游数据加密 key 修复、子执行 parked 清理、AI Assistant 预览修复

### 4. 跟版时效（长期价值）

- **CI 全自动产线**：上游 stable 出版 → 评估 → 翻译 → 构建 → Release → 镜像，全链无人值守（2.39.8 起实战验证）
- patch 版零人工；minor 跨越有预研预案，红灯窗口收敛到分钟级
- **质量门禁兜底**：词典覆盖率门禁（缺译阻断发版）+ 灰度验证六件套（YTJ1 先行：健康检查 / 品牌 / bundle hash / 新增文案抽查），带病版本到不了客户手里

### 5. 合规与安全

- **授权链清晰**：MIT（原作者 imblowsnow 书面授权 + BSI 延续维护），双语版权声明；n8n 本体 Sustainable Use License 合规，未删除或遮盖任何官方版权声明
- **产线安全加固**：版本号白名单校验、第三方 action SHA-pin、权限最小化、CodeQL + 依赖告警监控

## 对比参照

| 参照方案 | 对比结论 |
|---|---|
| 官方英文 n8n | 本方案 = 官方完整能力 + 全中文界面，随官方同步更新，升级路径完全一致 |
| 旧上游汉化包（blowsnow，停在 2.33.7） | 本方案持续跟版（当前 2.39.8），词典 8350 → 9522 键，旧包全部已知缺陷（含弃更后新增文案全英文）已解决 |
| 客户自行维护翻译 | 本方案自动化产线 + 翻译评审流程承接，客户零投入、零人员依赖 |

## 适用场景

| 客户场景 | 推荐形态 |
|---|---|
